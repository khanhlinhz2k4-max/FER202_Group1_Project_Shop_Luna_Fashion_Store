\chapter{Software Requirements Specification}

\section{Project Name \& Overview}
\textbf{Project Name:} LUNE Fashion Store -- Fashion E-Commerce Website

LUNE Fashion Store is a proposed e-commerce website designed to help customers discover, browse, and purchase fashion products online. In addition to customer-facing shopping features, the system provides an administration area where authorized administrators can manage products, monitor inventory, process orders, and view registered customer information.

The project aims to deliver a modern, convenient, and consistent online shopping experience. Its visual direction combines minimalism with a sense of luxury, reflected in the layout, product imagery, color palette, typography, and navigation structure. The system organizes its functions according to different user roles, helping customers find suitable products and enabling administrators to perform store management activities more efficiently.

LUNE Fashion Store is designed around three primary actors: Guest, Customer, and Admin. Each actor has a different set of permissions and responsibilities. This separation establishes a foundation for interface design, functional requirement definition, access control, and system testing.

For the initial interface-focused version, the project concentrates on the core functions of an online fashion store. Operations such as placing orders, updating order statuses, and selecting payment methods may be simulated to demonstrate the intended business workflow. If a backend or an external payment gateway has not been integrated, these features must not be considered real payment transactions.

\section{Context \& Proposed Solution}

\subsection{Project Context}
The growth of e-commerce has enabled customers to discover and purchase products through online platforms. In the fashion industry, customers often need to browse multiple products, compare prices, check sizes and colors, and review relevant product information before making a purchasing decision. A well-organized website can make product information easier to access and provide a clearer, more continuous shopping experience.

However, customers may encounter difficulties when product information is incomplete, search and filtering tools are inconvenient, or the cart and checkout processes are unnecessarily complicated. Customers may also need convenient ways to review their order information and manage their accounts when the corresponding features are available.

From a store management perspective, a fashion business needs to maintain product catalogs, prices, inventory quantities, and order statuses. Without consistent information management, administrators may experience difficulties updating product data, checking stock availability, and monitoring orders in progress. Therefore, the system should provide appropriate administrative functions to support product data management and order processing.

To address these needs, LUNE Fashion Store is proposed as an e-commerce solution combining a customer-facing storefront with an administrative portal. The system aims to consolidate essential shopping and management functions within a unified platform, making customer interactions more convenient and store operations more organized.

\subsection{Problems to Be Addressed}
The project focuses on addressing the following six key problems:
\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{First, difficulties in product discovery and selection:} When a store contains many products, customers need search, filtering, and sorting tools to identify items that match their preferences. Therefore, the system should provide an organized product catalog, keyword-based search, and appropriate filtering criteria.
    \item \textbf{Second, the need for clear product information:} Customers need to review product images, names, prices, descriptions, and relevant attributes before deciding to purchase an item. The product detail page should present sufficient information to help customers understand the product they are considering.
    \item \textbf{Third, the need for a convenient and consistent shopping process:} Customers should be able to add products to their cart, adjust quantities, review costs, and confirm their order information. Financial calculations must be consistent so that customers can understand the expected total before confirming an order.
    \item \textbf{Fourth, the need for organized product and order management:} Administrators need tools to create, update, and delete products, monitor inventory, review orders, and update order statuses according to defined business rules.
    \item \textbf{Fifth, the need for appropriate access control:} Guests, registered customers, and administrators have different responsibilities and information needs. The system should restrict access according to user roles and prevent unauthorized access to private information.
    \item \textbf{Sixth, the need for a responsive interface:} Customers may access the website using desktop computers, tablets, or mobile phones. Therefore, the interface should adapt to different screen sizes and remain usable across common devices.
\end{enumerate}

\subsection{Proposed Solution}
LUNE Fashion Store is proposed as a web-based e-commerce application consisting of four main solution areas:

\subsubsection{1. Customer Storefront}
The customer storefront provides the main functions needed for browsing and purchasing products:
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Home page:} Introduces the brand, highlights featured collections, and guides users to main product categories.
    \item \textbf{Search and product catalog:} Allows users to search by keyword, filter products by relevant criteria, and sort the product list.
    \item \textbf{Product details:} Displays product images, prices, descriptions, available options such as size or color when applicable, and current stock status.
    \item \textbf{Wishlist:} Allows users to save products of interest for later viewing.
    \item \textbf{Shopping cart:} Allows users to add products, change quantities, remove items, and review the temporary subtotal.
    \item \textbf{Checkout and order confirmation:} Collects recipient information, applies valid discount codes, selects a payment method, and creates an order.
    \item \textbf{Customer account and profile:} Supports registration, login, viewing personal information, and reviewing order history according to the implemented scope.
    \item \textbf{Support features:} May include a size guide, product quick view, printable invoice, or chatbot consultation if these features are implemented in the system.
\end{itemize}

\subsubsection{2. Admin Portal}
The administrative portal supports store management through the following functions:
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Dashboard:} Displays summary information such as product counts, order counts, customer counts, and revenue based on available system data.
    \item \textbf{Product management:} Supports viewing the product list, adding new products, updating product information, deleting products with confirmation, and controlling product visibility.
    \item \textbf{Inventory monitoring:} Displays stock quantities and identifies low-stock or out-of-stock products.
    \item \textbf{Order management:} Allows administrators to view orders, filter orders by status, and update order statuses according to the order lifecycle.
    \item \textbf{User management:} Allows administrators to create, view, edit, and delete registered user accounts while safeguarding active administrator permissions.
    \item \textbf{Voucher \& Review management:} Supports creating, editing, and toggling promotional discount vouchers via modal forms, as well as moderating customer product reviews (inspecting customer feedback in read-only mode, posting official LUNE Atelier replies, hiding inappropriate reviews, or removing spam).
\end{itemize}
Administrative features are designed to reduce unnecessary operations and prevent invalid data changes. Important actions, such as deleting a product, voucher, user, or review, include an appropriate confirmation step.

\subsubsection{3. Business Rules and Shopping Support}
The system applies consistent business rules to the shopping cart, order costs, discount codes, inventory, and order statuses. Under the proposed rules, orders with a product subtotal of at least USD 200 qualify for free shipping, while orders below this threshold incur a USD 15 shipping fee. The \texttt{LUNE10} discount code provides a 10\% discount on eligible product value.

The system also prevents customers from selecting quantities that exceed the available stock recorded in the current data source. When an eligible order is cancelled, its deducted inventory must be restored only once. Order status changes must follow the defined lifecycle to prevent invalid transitions.

\subsubsection{4. Multilingual and Multi-Device Support}
The system supports Vietnamese and English, allowing users to switch between the supported interface languages. The selected language is stored and restored during subsequent visits. The interface adapts to desktop computers, tablets, and mobile phones so navigation menus, product filters, shopping carts, and checkout forms are arranged appropriately for different screen sizes.

The system identifies three primary actors:

Customer-only features check the user's authentication status, while administrative features verify the Admin role. In a complete production system, access to protected data must also be enforced on the server side rather than relying solely on hiding or displaying interface components.

\subsection{Project Scope and Assumptions}
Within the analysis and interface-development scope of LUNE Fashion Store, the project focuses on the primary shopping workflow and administrative functions. The scope includes product display, search and filtering, product details, shopping cart, wishlist, checkout, account management, and the administration functions for products, inventory, orders, users, vouchers, and reviews.

Payment methods such as Cash on Delivery (COD), bank transfer (VietQR), and credit or debit cards are presented as interface options. Where the system is not integrated with an external bank settlement API, it simulates the selection of a payment method and does not execute real financial charges.

For a frontend prototype using mock data, information is stored through \texttt{localStorage}. Browser-based storage is distinguished from centralized server-side storage, as data stored in the browser is intended for single-client state persistence during demonstration and evaluation.

\section{Core Business Rules}

\subsection{Cart Grouping and Line Item Rule}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Variant Identification:} Cart items are distinguished by product identifier, selected size, and selected color (\texttt{id-size-color}).
    \item \textbf{Duplicate Variant Consolidation:} When a customer adds a product with the same product ID, size, and color as an existing cart item, the system increases the quantity of the existing line item rather than creating a duplicate row.
    \item \textbf{Distinct Variant Separation:} When a customer selects a different size or color for the same product, the system creates a separate line item in the cart.
    \item \textbf{Quantity Capping:} A line item's quantity must not exceed the available stock recorded for that product.
\end{itemize}

\subsection{Financial and Free Shipping Calculation Rule}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Subtotal:} Calculated as the sum of $\text{Unit Price} \times \text{Quantity}$ across all items in the shopping cart.
    \item \textbf{Shipping Fee:} Under the LUNE shipping policy, orders with a subtotal greater than or equal to USD 200 (\$200) qualify for complimentary free shipping (\$0). Orders with a subtotal below USD 200 incur a flat shipping fee of USD 15 (\$15).
    \item \textbf{Promotional Discount:} An eligible promotional discount is deducted according to the applicable voucher rules.
    \item \textbf{Grand Total:} Calculated consistently as:
    \[ \text{Grand Total} = \text{Subtotal} - \text{Discount} + \text{Shipping Fee} \]
\end{itemize}

\subsection{Inventory Lifecycle and Stock Control Rule}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Stock Availability:} Before an order is confirmed, the system verifies that requested quantities do not exceed available stock.
    \item \textbf{Stock Deduction:} When an order is placed, purchased quantities are automatically deducted from product inventory in \texttt{ShopContext}.
    \item \textbf{Stock Restoration:} When an eligible order is cancelled, purchased quantities are automatically restored to catalog inventory. The same cancellation never restores stock more than once.
    \item \textbf{Out-of-Stock Products:} Products with zero available stock (\texttt{stock = 0}) cannot be purchased and display an Out-of-Stock badge.
    \item \textbf{Low-Stock Notice:} Color-coded badges classify inventory into Green ($>10$ in stock), Orange ($1$--$10$ low stock), and Red ($0$ out of stock).
\end{itemize}

\subsection{Order State Transition Rule}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Initial Status:} Newly placed orders are assigned the initial status of \texttt{Pending}.
    \item \textbf{Order Progression:} Orders progress sequentially through the lifecycle: \texttt{Pending} $\rightarrow$ \texttt{Shipping} $\rightarrow$ \texttt{Delivered}.
    \item \textbf{Order Cancellation:} Customers can cancel orders while in \texttt{Pending} status; administrators can transition eligible orders to \texttt{Cancelled}, triggering automatic inventory restock.
    \item \textbf{Completed Orders:} A \texttt{Delivered} order cannot be returned to an earlier status through the normal workflow and unlocks verified buyer review submission.
    \item \textbf{Status Consistency:} Order status changes are reflected immediately across both the administrative table and the customer's 4-step \texttt{OrderTimeline}.
\end{itemize}

\subsection{Voucher Eligibility and Discount Rule}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Voucher Status:} A voucher must be marked active to be eligible for application.
    \item \textbf{Validity Period:} The current date must fall within the voucher's configured start date and expiration date.
    \item \textbf{Minimum Spending:} The order subtotal must meet or exceed the voucher's minimum spending threshold (\texttt{minSubtotal}).
    \item \textbf{Percentage Discount:} Calculated as $\text{Subtotal} \times (\text{Discount Rate} / 100)$.
    \item \textbf{Fixed Discount:} Deducts a fixed USD value, capped so the discount never exceeds the eligible subtotal.
    \item \textbf{Order Record:} When an order is placed using a voucher, the applied voucher code and discount amount are recorded in the order payload.
\end{itemize}

\subsection{Product Visibility and Preview Rule}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Product Visibility:} Products marked as inactive (\texttt{isActive = false}) via the 1-click \texttt{Eye/EyeOff} toggle are excluded from customer-facing product listings, Home page sections, and Live Search results.
    \item \textbf{Inventory Preservation:} Toggling a product's visibility preserves all of its underlying stock and metadata records.
    \item \textbf{Administrative Access (Admin Preview Mode):} Authorized administrators opening a hidden product page view it safely under \textit{Admin Preview Mode} with an amber informational banner.
    \item \textbf{Customer Access:} Inactive products are blocked from normal customer purchase interactions.
\end{itemize}

\subsection{Verified Customer Review \& Moderation Rule}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Review Eligibility:} Customers can submit verified reviews for delivered orders from their profile order history or through the interactive review modal on the product detail page.
    \item \textbf{Review Integrity (Read-Only Customer Content):} Once submitted by a customer, the star rating, review title, and review comment are strictly immutable to administrators. Administrators cannot alter customer opinions or create synthetic reviews.
    \item \textbf{Official Atelier Response:} Administrators may attach or update an official brand response (\texttt{adminReply}) to any customer review, which is displayed directly beneath the customer's comment on the storefront.
    \item \textbf{Visibility Moderation \& Rating Calculation:} Public average star ratings and 5-star distribution bars are dynamically calculated exclusively from visible reviews (\texttt{isHidden !== true}). Hiding or deleting a review immediately updates the product's public rating metrics.
\end{itemize}

\section{UI/UX Design Principles}

\subsection{Design Goals}
The overarching visual philosophy of LUNE Fashion Store is articulated through the concept of \textbf{"Warm Luxury $\times$ Modern Trendy $\times$ Tactile Natural Grace"}. Rather than adhering to conventional aggressive commercialization, LUNE delivers an editorial, quiet luxury e-commerce experience reminiscent of high-end international fashion lookbooks (e.g., Paris Atelier ready-to-wear publications). The core design objectives encompass:
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Balanced Unisex Representation (50\% Female / 50\% Male Visual Parity):} A strict design rule established in the brand master specification is that LUNE is not an exclusive womenswear boutique, cosmetics shop, or bridal salon. The store provides an equitable 50/50 balance between Women's and Men's ready-to-wear collections. Imagery, curated categories, hero slides, and product showcases celebrate both masculine tailoring and soft feminine warmth.
    \item \textbf{Warmth over Clinical Minimalism (Quiet Luxury):} Unlike sterile, stark monochrome storefronts (pure black \texttt{\#000000} and hospital white \texttt{\#FFFFFF}), LUNE utilizes warm organic tones inspired by unbleached linen, raw mulberry silk, and dark cocoa beans. This creates an inviting, tactile digital atmosphere that encourages relaxed, thoughtful browsing.
    \item \textbf{Frictionless Shopper Usability:} Aesthetic refinement is paired with effortless e-commerce ergonomics. Key interactive components---such as dynamic category synchronization, real-time live search with trending chips, and responsive product grids---ensure shoppers can discover silhouettes, verify sizing, and execute purchases in three clicks or fewer.
    \item \textbf{Restraint and Visual Discipline (Do NOTs):} The interface strictly avoids excessive glassmorphism, heavy drop-shadows, juvenile cartoonish decorations, and jarring neon call-to-actions. Micro-interactions and state changes rely on smooth, subtle B\'{e}zier transitions (\texttt{cubic-bezier(0.16, 1, 0.3, 1)}) and understated 1px borders.
\end{itemize}

        \item \textit{Google Fonts:} Playfair Display and Cormorant Garamond for editorial serif headings, together with Montserrat for body text and interface content.

    \item \textbf{Iconography and Visual Effects:}
    \begin{itemize}[nosep]

    \item \textbf{Client-Side Data Persistence:}

    \end{itemize}
\end{enumerate}

\subsection{Frontend Architecture}
The front end follows a component-driven Single Page Application (SPA) architecture. React components organize the user interface, while the Context API provides shared application state through \texttt{ShopContext.jsx} and \texttt{LanguageContext.jsx}:
\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{Centralized State Management (\texttt{ShopContext.jsx}):} Provides shared state and business operations through the custom hook \texttt{useShop()}. It manages product records, cart items, order history, the current user session, and promotional vouchers. It coordinates adding and removing cart items, updating quantities, placing orders, and managing inventory changes. Cart items are distinguished by product variant (\texttt{id}, \texttt{size}, and \texttt{color}) and persisted to \texttt{localStorage}.
    \item \textbf{Bilingual Internationalization (\texttt{LanguageContext.jsx}):} Implements a client-side internationalization system for Vietnamese (\texttt{vi}) and English (\texttt{en}). It provides translation functions \texttt{t(path, fallback)} for interface text and \texttt{tp(product, field)} for localized product attributes, backed by 967 keys in \texttt{translations.js}.
    \item \textbf{Client-Side Route Protection (\texttt{ProtectedRoute.jsx}):} Checks the current user and assigned role before allowing access to protected interface routes, including \texttt{/profile} and \texttt{/admin/*}.
    \item \textbf{Global Error Handling (\texttt{ErrorBoundary.jsx}):} Wraps the application tree and catches rendering errors within its scope, displaying a luxury fallback recovery interface with actions for clearing session-related storage keys and returning to the home or login page.
    \item \textbf{Scroll and Route Anchor Handling (\texttt{ScrollToTop}):} Implemented within \texttt{App.jsx} to monitor route and hash changes. When a URL contains a hash, it scrolls smoothly to the target element with a \texttt{scroll-margin-top} of \texttt{90px} to prevent fixed navigation bar occlusion; otherwise, it scrolls the viewport to the top of the page.
\end{enumerate}

\section{Sitemap and User Flow Specifications}

\subsection{Sitemap \& Navigation Architecture Analysis}
The LUNE Fashion Store web application is built on React 19 and React Router v7 as a Single Page Application (SPA). The application navigation architecture is segmented into two distinct privilege domains:
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Client Storefront (Public \& Authenticated Client Domain):} Designed with a "Warm Luxury \& Quiet Elegance" aesthetic, featuring full internationalization (i18n: English / Vietnamese), a global slide-in cart drawer (\texttt{CartDrawer}), personal lookbook wishlist (\texttt{/wishlist}), catalog exploration (\texttt{/shop}), product detail view (\texttt{/product/:id}), checkout pipeline (\texttt{/checkout}, \texttt{/order-success}), authentication (\texttt{/login}, \texttt{/register}), member profile hub (\texttt{/profile}), and an Atelier AI Stylist chatbot.
    \item \textbf{Admin Portal (Administrative Domain):} Secured by role-based access control via \texttt{ProtectedRoute} (requiring \texttt{currentUser.role === 'admin'}), providing comprehensive business dashboard analytics (\texttt{/admin}) and full CRUD interfaces for products (\texttt{/admin/products}), orders (\texttt{/admin/orders}), users (\texttt{/admin/users}), vouchers (\texttt{/admin/vouchers}), and customer reviews (\texttt{/admin/reviews}).
\end{itemize}

\subsection{Shopping Flow}
The shopping flow guides the customer from initial discovery through product selection to cart inspection without breaking browsing continuity:
\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{Discovery \& Exploration:}
    \begin{itemize}[nosep]
        \item The user browses featured collections on the Home page (\texttt{/}) or navigates to the dedicated catalog at \texttt{/shop}.
        \item The customer filters items by fashion category, garment type, size, color, or price range, or conducts keyword searches via the global live search bar in the \texttt{Navbar}.
    \end{itemize}
    \item \textbf{Product Configuration \& Inventory Validation:}
    \begin{itemize}[nosep]
        \item Selecting a product card navigates to \texttt{ProductDetailPage} (\texttt{/product/:id}) or opens the \texttt{QuickViewModal}.
        \item The customer selects their required size (\texttt{selectedSize}: XS, S, M, L, XL) and color swatch (\texttt{selectedColor}).
        \item The application checks inventory availability (\texttt{product.stock}). If stock is zero, purchase actions are disabled and an "Out of Stock" indicator is rendered.
    \end{itemize}
    \item \textbf{Cart Addition (\texttt{addToCart}):}
    \begin{itemize}[nosep]
        \item When clicking "Add to Cart", the \texttt{addToCart} handler in \texttt{ShopContext} inspects the existing cart collection.
        \item If an item with the matching \texttt{id}, \texttt{selectedSize}, and \texttt{selectedColor} already exists, its quantity is incremented (capped by available stock).
        \item If it is a new variant or product, a distinct item entry is constructed with a unique composite identifier and added to the cart.
        \item The cart state is instantly synchronized with \texttt{localStorage} (\texttt{lune\_cart}).
    \end{itemize}
    \item \textbf{Non-Disruptive Cart Drawer Interaction (\texttt{CartDrawer}):}
    \begin{itemize}[nosep]
        \item Cart addition triggers \texttt{setIsCartOpen(true)}, sliding the cart drawer in smoothly from the right viewport edge.
        \item Body scroll locking (\texttt{document.body.style.overflow = 'hidden'}) is activated to prevent background scrolling distractions.
        \item The customer inspects item summaries, adjusts quantities, monitors the \$200 Free Shipping Progress Meter, and chooses either to proceed to \texttt{/checkout} or continue browsing.
    \end{itemize}
\end{enumerate}

\subsection{Authentication Flow}
The Authentication Flow coordinates user identity verification, account registration, password complexity validation, and role-based route authorization. It ensures seamless onboarding while safeguarding administrative capabilities against unauthorized access:
\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{User Registration \& Password Strength Evaluation:}
    When registering at \texttt{/register}, input fields (Full Name, Email, Username, Password, Confirm Password) are continuously validated on blur and on submit. A dynamic Password Strength Meter evaluates four criteria: minimum length ($\ge 8$ characters), mixed casing (uppercase and lowercase), numeric digits, and special characters (\texttt{!@\#\$\%\textasciicircum\&*}). The visual indicator grades complexity into \textit{Weak} (red), \textit{Medium} (amber), and \textit{Strong \& Secure} (emerald). Upon passing validation and confirming no duplicate email/username exists in \texttt{lune\_users}, the system commits the entity with \texttt{role: 'user'} and redirects to \texttt{/login} with prefilled credentials.
    \item \textbf{Credential Verification \& Session Initialization:}
    At \texttt{/login}, users enter their identifier (email or username) and password, or choose the convenient 1-Click Demo buttons ("Demo Customer" or "Demo Admin") provided for evaluation. The authentication engine queries \texttt{lune\_users} in \texttt{LocalStorage}. If credentials match, an active session is committed to \texttt{lune\_current\_user}. If the user checked "Remember Me", the identifier is stored in \texttt{lune\_remembered\_identifier}.
    \item \textbf{Role-Based Route Protection (\texttt{ProtectedRoute.jsx}):}
    The \texttt{ProtectedRoute} wrapper acts as a client-side navigation guard. Unauthenticated requests to \texttt{/profile} or \texttt{/admin} are intercepted and redirected to \texttt{/login} with \texttt{state.from} preserved. If an authenticated user with \texttt{role: 'user'} attempts to access \texttt{/admin}, \texttt{ProtectedRoute} blocks the transition, displays an access denial notification, and routes the user safely to the storefront root (\texttt{/}), eliminating infinite redirection loops.
\end{enumerate}

\subsection{Order Flow}
The order fulfillment flow orchestrates checkout data collection, discount logic, payment verification, and transaction persistence:
\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{Checkout Initialization:}
    Triggered from \texttt{CartDrawer}. If the cart is empty, the customer is prompted to explore the boutique; otherwise, the router transitions to \texttt{/checkout}.
    \item \textbf{Shipping Destination Setup:}
    \begin{itemize}[nosep]
        \item \textit{Authenticated Customers:} Reads saved destinations from the client's Profile Address Book (\texttt{lune\_addresses\_\{email\}} in \texttt{localStorage}), enabling 1-click default destination selection.
        \item \textit{New / Custom Destination:} Customers can enter recipient name, telephone number, email, and detailed street address, with an option to save the destination to their profile address book.
        \item \textit{Validation:} Complete client-side validation prevents submission if recipient name, phone number, or delivery address are missing or malformed.
    \end{itemize}
    \item \textbf{Privilege Voucher Application:}
    The application inspects active boutique promotions from \texttt{vouchers} state:
    \begin{itemize}[nosep]
        \item \textit{Automated Dropdown Selector:} Presents pre-qualified vouchers (\texttt{eligibleVouchers}) where \texttt{cartTotal >= voucher.minSubtotal}.
        \item \textit{Upsell Prompts for Locked Vouchers:} Displays locked vouchers requiring higher spends (e.g., "Add \$35 more to unlock VIP30").
        \item \textit{Manual Coupon Code Entry:} Users can input coupon codes (e.g., \texttt{LUNE10}), which undergo real-time validation against expiry dates, active flags, and minimum spend rules before computing instant discounts.
    \end{itemize}
    \item \textbf{Payment Method Selection:}
    \begin{itemize}[nosep]
        \item \textit{International Credit / Debit Card (USD Standard):} Interactive luxury card simulation (Visa, Mastercard, AMEX) complete with cardholder name, card number, expiry, and CVV fields conforming to 256-bit SSL interface guidelines.
        \item \textit{Vietnam Domestic Bank Transfer (VietQR -- VND):} Real-time currency conversion ($1.00\text{ USD} \approx 25,400\text{ VND}$), dynamically generating an official Napas 24/7 QR code via \texttt{api.vietqr.io} embedded with recipient MB Bank account \texttt{0988888888}, account holder \texttt{LUNE ATELIER STORE}, converted amount, and unique order memo (\texttt{orderMemo}), accompanied by 1-click clipboard copying.
        \item \textit{Cash on Delivery (COD):} Standard post-inspection cash settlement on arrival.
    \end{itemize}
    \item \textbf{Order Commitment \& Stock Depletion (\texttt{addOrder}):}
    Executing checkout invokes \texttt{addOrder()} in \texttt{ShopContext}:
    \begin{itemize}[nosep]
        \item Generates a unique alphanumeric order identifier (e.g., \texttt{LUNE-4819}).
        \item \textit{Automated Stock Depletion:} Decrements the \texttt{stock} attribute of each purchased garment in \texttt{products} state.
        \item \textit{Cart Reset:} Empties the shopping bag via \texttt{clearCart()}.
        \item \textit{Order Persistence:} Stores the order in \texttt{orders} state and commits to \texttt{localStorage} (\texttt{lune\_orders}).
    \end{itemize}
    \item \textbf{Order Confirmation \& Boutique Invoicing:}
    The customer is routed to \texttt{/order-success} with the order payload passed in router state, displaying the receipt overview, items snapshot, payment status, and the real-time 4-stage fulfillment tracker (\texttt{OrderTimeline}). Clicking "Print Boutique Invoice" launches \texttt{InvoiceModal}, an A4-optimized printable invoice mounted onto \texttt{document.body} via React Portals with dedicated \texttt{@media print} stylesheets.
\end{enumerate}

\section{Frontend Component Structure}
The frontend architecture of LUNE Fashion Store is organized into five main areas: \textit{App Structure}, \textit{Shared and Global Components}, \textit{Storefront Routes}, \textit{Admin Routes}, and \textit{Context \& Data}:
\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{App Structure:} The \texttt{App} component in \texttt{src/App.jsx} serves as the main entry point, wrapped by \texttt{ErrorBoundary} to handle rendering errors, \texttt{BrowserRouter} for client-side navigation, \texttt{LanguageProvider} for bilingual settings, and \texttt{ShopProvider} for shared shopping state.
    \item \textbf{Shared and Global Components:} Includes \texttt{Navbar} (smart hide-on-scroll-down and reveal-on-scroll-up sticky behavior), \texttt{Footer}, \texttt{CustomSelect} (rendered via React Portal), \texttt{ChatBot} (24/7 AI styling support), \texttt{CartDrawer}, \texttt{WishlistToast}, \texttt{ScrollToTop}, \texttt{GoldenCursorTrail}, and \texttt{ProtectedRoute}.
    \item \textbf{Storefront Routes:} Contains \texttt{HomePage}, \texttt{ShopPage}, \texttt{ProductDetailPage}, \texttt{WishlistPage}, \texttt{CheckoutPage}, \texttt{OrderSuccessPage}, \texttt{LoginPage}, \texttt{RegisterPage}, and \texttt{ProfilePage} (protected by \texttt{ProtectedRoute}), supported by \texttt{ProductCard}, \texttt{QuickViewModal}, \texttt{SizeGuideModal}, \texttt{ReviewModal}, \texttt{InvoiceModal}, and \texttt{OrderTimeline}.
    \item \textbf{Admin Routes:} Protected by \texttt{ProtectedRoute} with \texttt{requireAdmin} enabled, rendering \texttt{AdminLayout} and its six administrative modules: \texttt{AdminDashboard}, \texttt{AdminProducts}, \texttt{AdminOrders}, \texttt{AdminUsers}, \texttt{AdminVouchers}, and \texttt{AdminReviews}.
    \item \textbf{Context and Data:} \texttt{ShopContext} and \texttt{LanguageContext} distribute state and actions across the component tree, backed by initial catalog records in \texttt{src/data/products.js} and bilingual dictionaries in \texttt{src/data/translations.js}.
\end{enumerate}

    \item \textbf{Cancelling a Pending Order:} If an order has just been placed and retains \texttt{Pending} status, locate the \textbf{Cancel Order} button on the card. Click it and confirm the prompt dialog. The order status updates to \texttt{Cancelled} immediately, and items are safely returned to warehouse stock.
    \item \textbf{Submitting a Verified Review:} Once an order reaches \texttt{Delivered} status, click the \textbf{Write a Review} button. In the interactive \texttt{ReviewModal}, rate the garment from 1 to 5 stars, write feedback on fabric drape and tailoring, and submit. The review features an official \textbf{Verified Buyer} badge on the product page.
\end{enumerate}

\subsection{Admin Guide}
The Admin Guide explains how a store manager operates the Administrator Portal, from signing in to moderating customer reviews:

\subsubsection{Step 1: Sign In to the Administrator Portal}
\begin{enumerate}[leftmargin=1.2cm]
    \item Open \texttt{/login} and click \textbf{Demo Admin} (\texttt{admin@lune.com} / \texttt{Admin@123}), or type the admin credentials manually, then click \textbf{SIGN IN}.
    \item The system redirects to \texttt{/admin}. Standard customer accounts are blocked from this area.
    \item The \texttt{VI | EN} pill switcher in the top bar changes the language of the whole portal; \textbf{Sign Out} at the bottom of the sidebar ends the session.
\end{enumerate}

\subsubsection{Step 2: View KPIs and Charts}
\begin{enumerate}[leftmargin=1.2cm]
    \item On the Dashboard, read the four KPI cards: Total Revenue, Total Orders, Total Products, and Total Customers.
    \item Hover over the 7-Day Revenue Area Chart to see the exact revenue of each day, and use the Category Donut Chart to compare Women, Men, and Accessories.
    \item Check the table of the 5 latest orders for items that need attention.
\end{enumerate}

\subsubsection{Step 3: Add and Edit Products}
\begin{enumerate}[leftmargin=1.2cm]
    \item Open \textbf{Products} in the sidebar. Use the search bar or category filter to find items.
    \item Click \textbf{+ Add New Product}, fill in title, category, price, stock, image URLs, sizes, colors, and description, then click \textbf{Save Product}.
    \item To change a product, click the \textbf{Edit} (pencil) icon, update the fields, and click \textbf{Update}.
    \item Click the \textbf{Eye / EyeOff} icon to hide or show a product on the storefront, or the \textbf{Trash} icon and \textbf{Confirm Delete} to remove it permanently. Watch the stock badge (green / orange / red) to know when to restock.
\end{enumerate}

\subsubsection{Step 4: Manage Vouchers}
\begin{enumerate}[leftmargin=1.2cm]
    \item Open \textbf{Vouchers} and click \textbf{+ Create Voucher}.
    \item Enter the code, discount type (percent or fixed), value, minimum subtotal, start date, and expiry date, then save.
    \item Use the \textbf{Edit} icon to change a voucher, the \textbf{Eye} icon to activate or deactivate it, and the \textbf{Trash} icon to delete an expired code.
\end{enumerate}

\subsubsection{Step 5: Process Orders}
\begin{enumerate}[leftmargin=1.2cm]
    \item Open \textbf{Orders}, search by order ID or customer, and filter by status with the dropdown.
    \item Click the status control to move an order from \texttt{Pending} to \texttt{Shipping}, then \texttt{Delivered}. The customer's timeline updates automatically.
    \item To cancel an order, choose \texttt{Cancelled}; the ordered quantities are returned to stock automatically.
\end{enumerate}

\subsubsection{Step 6: Reply to and Moderate Reviews (\texttt{/admin/reviews})}
\begin{enumerate}[leftmargin=1.2cm]
    \item Open \textbf{Reviews} and filter by keyword, star rating, or visibility.
    \item Click the \textbf{Reply} (\texttt{MessageSquare}) icon. The customer's original review is read-only; type the official \textbf{LUNE Atelier Response} and save. It appears under the review on the product page.
    \item Use the \textbf{Eye / EyeOff} icon to hide or restore a review, and the \textbf{Trash} icon to delete spam after confirmation.
\end{enumerate}

\section{Installation Manual}

\subsection{Prerequisites}
Before running the LUNE Fashion Store project, ensure that the following software is installed:
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Node.js:} Version 18 or later.
    \item \textbf{npm:} Used to install and manage project dependencies.
    \item \textbf{Git:} Used to clone the project repository.
    \item \textbf{Web Browser:} Google Chrome or Microsoft Edge.
\end{itemize}

\subsection{How to Run the Project Locally}
Follow these steps to install and run the LUNE Fashion Store application on a local computer:
\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{Step 1 -- Clone the repository:}
\begin{verbatim}
git clone https://github.com/khanhlinhz2k4-max/FER202_Group1_Project_Shop_Luna_Fashion_Store.git
\end{verbatim}
    \item \textbf{Step 2 -- Navigate to the project directory:}
\begin{verbatim}
cd FER202_Group1_Project_Shop_Luna_Fashion_Store
\end{verbatim}
    \item \textbf{Step 3 -- Install dependencies:}
\begin{verbatim}
npm install
\end{verbatim}
    \item \textbf{Step 4 -- Start the development server:}
\begin{verbatim}
npm run dev
\end{verbatim}
    \item \textbf{Step 5 -- Access the application:}
    After the development server starts successfully, open a web browser and navigate to:
    \url{http://localhost:5173}
\end{enumerate}
